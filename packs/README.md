# 양식 팩 (공개 규약)

이 저장소는 **로컬 LLM CLI 엔진**입니다. 용도는 팩입니다. 그램에 풀린 exe 이름은 `로컬LLM`일 뿐입니다.

```
추출·수확·검수(엔진, 코드) → 팩 프롬프트로 JSON → 워드
```

엔진은 MIT로 이 저장소에 둡니다. 고객 맞춤 문장·섹션 제목·허용 숫자는 팩에만 둡니다. 용도마다 GitHub 저장소를 새로 만들지 않습니다.

## 로드 순서

1. exe 옆 `packs/` (푼 ZIP에 같이 있으면 이게 이김)
2. 현재 폴더 `packs/`
3. exe 안에 심어 둔 기본 팩

정본 소스: `gramapp/packs/`

## 기본 팩 (이 저장소)

| 폴더 | 용도 | 결과 |
|---|---|---|
| `보고서` | 장표·PDF 보고 | `*_보고서/보고서.docx` |
| `회의록` | 전사·녹취 | `*_회의록/회의록.docx` |
| `번역` | 일한 직번역 | `*_번역/한국어번역.docx` |

## 새 팩 파일

폴더 하나에 세 파일이면 됩니다.

| 파일 | 역할 |
|---|---|
| `pack.json` | 이름, 결과 경로. 엔진이 읽는 키는 아래만 |
| `chunk.txt` | 조각마다 사실 JSON을 채우는 시스템 프롬프트 |
| `assemble.txt` | 사실들을 주제별 JSON으로 묶는 시스템 프롬프트 |

`pack.json`:

```json
{
  "id": "보고서",
  "label": "보고서",
  "blurb": "장표·PDF·자료를 한글 보고서로",
  "title_suffix": "보고서",
  "out_suffix": "_보고서",
  "out_name": "보고서.docx",
  "body_heading": "내용"
}
```

키를 바꾸거나 빼면 안 됩니다. 새 키는 엔진이 무시합니다. `id`는 메뉴 번호 옆 이름과 같습니다.

## 엔진이 채우라고 하는 JSON (assemble)

팩 프롬프트가 다른 말을 해도, 엔진은 이 모양만 워드로 옮깁니다.

```json
{
  "title": "",
  "date": "",
  "time": "",
  "place": "",
  "attendees": "",
  "agenda": "",
  "exec": [""],
  "sections": [{ "heading": "1. 개요", "facts": [""] }],
  "actions": [""]
}
```

숫자는 엔진이 원문에서 걷습니다. 목록에 없는 숫자는 〔원문 확인〕으로 바뀝니다. 팩이 숫자를 창작하면 안 됩니다.

## 여기 올리지 말 것
